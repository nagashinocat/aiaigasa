# 絶対に相合傘をやめさせないゲーム Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 押すと雨が強まり離すと弱まる操作で、相合傘の二人の会話を最後のデートの約束(夕方の虹)まで守り切る、スマホブラウザ向けゲームを作る。

**Architecture:** ゲームの決まりごと(雨の強さ・帯・猶予・ドキドキ・勝敗)は描画から切り離した純粋なJSモジュールにし、Nodeでテストする。描画は「空と街の背景(2D Canvas)」「雨(WebGL、だめなら2D)」「ふきだしとメーター(HTML/CSS)」の3層。main.js が毎フレーム logic を進め、結果を各層に渡す。

**Tech Stack:** HTML / CSS / ES Modules(ビルドなし)、WebGL1、Canvas 2D、テストは `node --test`、画面確認は Playwright(1.63)。外部ライブラリなし。

**Spec:** `docs/superpowers/specs/2026-11-18-aiaigasa-design.md`

**設計書からの変更(私の判断):** 設計書の「HTML1ファイル」は、テストしやすさのため `index.html` + 小さなJSファイル群に変更。ビルド不要で、そのまま静的ホスティング(GitHub Pages など)に置ける。

## Global Constraints

- 文言・UIはすべて日本語。タイトル「絶対に相合傘をやめさせないゲーム」
- スマホ縦画面が基準(390×844 で崩れない)。PCでもマウスで遊べる
- 1プレイ 1〜2分(何も失敗しなければ約90秒でクリア)
- 外部ライブラリ・外部通信なし。音なし
- 失敗時のせりふは必ず「また明日」を含む
- クリア演出:雨が止む → 空が夕焼け色 → 虹がゆっくりかかる
- キャラクターは傘と二人のシルエットのみ

## Review Focus

- アプリ切替やタブ非表示から戻ったとき(dtが数秒になる)→ 一気にゲームオーバーにならない(dtを0.1秒で頭打ち)
- 押したまま指が画面外へ出る/着信などで中断 → 押しっぱなし扱いにならない(pointerup/pointercancel/blurで離した扱い)
- スマホの長押しで文字選択・拡大鏡・右クリックメニューが出る → 出ない
- WebGLが無い、または途中でコンテキストを失う → 2Dの雨に切り替わって遊び続けられる
- 画面回転・リサイズ → キャンバスが引き伸ばされず描き直される

### Task 1: ゲームの決まりごと(logic.js)

**Files:**
- Create: `src/logic.js`, `tests/logic.test.js`, `package.json`(`{"type":"module","scripts":{"test":"node --test tests/"}}`)

**Interfaces:**
- Produces:
  - `export const CONFIG` — 下の値をそのまま持つオブジェクト
  - `export function createState(): State`
  - `export function step(state: State, dt: number, pressing: boolean, climax: boolean): State` — 新しいStateを返す(元は変えない)
  - `State = { rain: number, grace: number, doki: number, outcome: 'playing'|'closed'|'shelter'|'clear', time: number }`
  - `export function band(climax: boolean): {low:number, high:number}`

CONFIG の値(遊びながら調整してよい初期値):
```js
{ rainStart: 0.5, pressRate: 0.35, drift: 0.12, climaxDrift: 0.22,
  band: {low: 0.35, high: 0.65}, climaxBand: {low: 0.42, high: 0.58},
  graceMax: 2.0, graceRecover: 0.5, dokiRate: 1/90, maxDt: 0.1 }
```
- 毎ステップ: dt を `maxDt` で頭打ち → rain += (pressing ? pressRate : 0) − (climax ? climaxDrift : drift) を dt 倍、0〜1に収める
- 帯の中: doki += dokiRate·dt、grace は graceRecover·dt ずつ graceMax まで回復
- 帯の外: grace −= dt。0以下で outcome = rain < low ? 'closed' : 'shelter'
- doki ≥ 1 で outcome = 'clear'。outcome が 'playing' 以外なら何も変えずに返す

- [ ] **Step 1: 失敗するテストを書く** — `tests/logic.test.js`:
  - `starts in band`: createState() の rain は 0.5、outcome 'playing'、doki 0
  - `pressing raises rain, releasing lowers it`: 0.05秒×10回 押すと rain > 0.5、離すと < 0.5
  - `rain clamps to 0..1`
  - `too weak too long closes umbrella`: rain=0.1 で 0.1秒×21回(2.1秒)離し続けると outcome 'closed'
  - `too strong too long goes to shelter`: rain=0.95 で押し続け 2.1秒 → 'shelter'
  - `brief slip does not end game`: 帯外 1秒 → まだ 'playing'
  - `doki fills in band and clears`: rainを帯内に保つよう押す/離すを交互に約90秒回すと 'clear'、85秒時点ではまだ 'playing'
  - `climax narrows band`: band(true) が {low:0.42, high:0.58}
  - `huge dt is capped`: step(s, 5, false, false) の後でも grace > 0 で 'playing'
  - `finished state is frozen`: outcome 'closed' の state は step しても同じ値
- [ ] **Step 2:** `npm test` → FAIL(モジュールなし)
- [ ] **Step 3:** `src/logic.js` を上の仕様どおり実装
- [ ] **Step 4:** `npm test` → PASS
- [ ] **Step 5:** `git add -A && git commit -m "feat: core rain/doki logic"`

### Task 2: 会話(story.js)

**Files:**
- Create: `src/story.js`, `tests/story.test.js`

**Interfaces:**
- Produces:
  - `export const LINES: Array<{at:number, who:'he'|'she', text:string, climax?:boolean}>` — `at` はそのせりふが出るドキドキ値(0〜1、昇順)
  - `export function lineAt(doki: number): {index:number, line} | null` — `at <= doki` の最後のせりふ、なければ null
  - `export function isClimax(doki: number): boolean` — 今のせりふが climax か
  - `export const GOODBYE = {closed: string, shelter: string}`、`export const PROMISE: string`

- 会話は12〜15行の短い帰り道の物語。最初は他愛ない話(急な雨、傘を忘れた)、中盤で少し打ち解け、`at` 0.85〜0.97 あたりに climax の「あのさ…」「…なに?」を置く。最後(at 1.0 の直前)にデートの約束。PROMISE は「今度の日曜、一緒に出かけない?」の趣旨
- GOODBYE.closed は傘を閉じて「止んだね。…じゃあ、また明日」、shelter は軒下で「すごい雨…今日はここで。また明日」の趣旨

- [ ] **Step 1: テスト** — `LINES is sorted by at`、`lineAt(0)` は最初のせりふ(at 0)、`lineAt(0.5)` は at≤0.5 の最後、`at least one climax line between 0.8 and 1`、`GOODBYE texts include また明日`、`12..15 lines`

### Task 5: 雨(rain2d.js, rainGL.js, rain.js)

**Files:**
- Create: `src/rain2d.js`, `src/rainGL.js`, `src/rain.js`
- Modify: `src/main.js`, `index.html`(雨キャンバスを背景の上に重ねる、pointer-events:none)

**Interfaces:**
- 共通: `{ resize(w,h,dpr), draw(rain:number, dt:number, t:number), dispose() }`
- `export function createRain2D(canvas): Rain`
- `export function createRainGL(canvas): Rain | null` — WebGL不可なら null
- `export function createRain(canvas, onFallback?: () => void): Rain & {kind: 'gl'|'2d'}` — まず GL、だめなら 2D。`webglcontextlost` で 2D に差し替え(キャンバスを作り直して差し替える)。初めの2秒の平均フレーム時間が 40ms を超えたら 2D に落とす

- 2Dの雨:奥・中・手前の3層。層ごとに長さ・太さ・速さ・透明度を変える。数は rain に比例(最大でも合計 600 本程度)。地面に波紋の楕円が広がって消える
- GLの雨:全画面1枚のフラグメントシェーダ。(a) 奥行きのある雨筋(複数層、手前ほど太く・ぼける)、(b) 画面に付いて流れ落ちる水滴が背景キャンバスの絵をゆがめて映す(背景キャンバスをテクスチャとして毎フレーム渡す)、(c) 街灯の位置で雨筋がほのかに光る。強さ uniform `u_rain` で密度・速さ・水滴数が変わる。精度は mediump、解像度は dpr を最大 2 に抑える
- 背景キャンバスをGLが映す場合、背景キャンバス自体は非表示にしてGLの出力だけを見せる(二重に見えないように)。2Dのときは背景の上に雨を重ねる

- [ ] **Step 1:** rain2d.js を実装し、main.js で `createRain` 経由で表示(GL未実装の間は null を返す)
- [ ] **Step 2:** e2e:`?rain=2d` で強制 2D、`__game.rainKind` が '2d'、雨強・雨弱のスクリーンショット。`node tests/e2e.mjs` → e2e ok
- [ ] **Step 3:** rainGL.js を実装
- [ ] **Step 4:** e2e:既定で `__game.rainKind` が 'gl'(headless Chromium は SwiftShader で WebGL が動く。`--use-gl=swiftshader` を付ける)。雨強・雨弱を撮影。さらに `WEBGL_lose_context` 拡張で loseContext() を呼び、`rainKind` が '2d' に変わってゲームが続くこと
- [ ] **Step 5:** 2D/GL の画像を目で見比べ、GLの方が明らかに綺麗(奥行き・水滴のゆがみ)であること。そうでなければ直す
- [ ] **Step 6:** commit `feat: WebGL rain with 2D fallback`
